## 需要继续完成的核心功能

### 模板编辑与签发渲染

优先处理，这是学校实际制作奖状的主要功能缺口：

- frontend/src/views/business/templates.vue 中“添加文本、上传背景、添加公章位”按钮没有事件处理。
- 当前编辑器只保存标题、字号、颜色和两个显示选项，没有完整的图层编辑、字段拖放、背景上传或公章定位。
- backend/awards/renderer.py 的 render_unsigned 使用固定标题、坐标和测试文案，没有读取批次的模板快照或上传的公章图片。
- 编号显示开关、编号水印和其他模板设置没有应用到最终 PDF；页面的水印示意目前也是固定“测试专用”。
- BatchViewSet.perform_create 自动选择最近的已发布模板及公章版本，输出固定为 PDF 和 PNG，缺少每批选择模板、具体印章及输出形式的操作。

应完成“编辑保存模板、配置本批模板与公章、预览真实名单、会签、按快照生成”闭环。使用明显不同的背景和公章验证输出确实变化，同时确认历史证书不被重写。

### 管理界面与业务入口

- 账号与部门目前主要提供只读选项接口和 Django 维护后台，Pure Admin 中缺少完整的新建负责人、部门管理员和部门授权管理。

- 消息接口和部分通知已有实现，但提交、审批、签发完成等全流程通知还需逐项接通。
- 临时文件和普通日志的定期清理待补。备份脚本和恢复记录存在，但定时备份调度及失败通知尚缺完整验收证据。

### 权限和任务一致性

以下来自静态审查，未对线上数据做越权写入复现，应先用独立测试数据补测试，再修复：

- TemplateViewSet 继承完整 ModelViewSet，已发布模板列表全校可见；save_version 有部门判断，但通用更新、删除路径没有相应所属部门限制。
- SealViewSet 的列表和对象读取限制部门，但新建公章还需在创建校验中限制目标部门；只限制列表不能保护创建。
- submit_batch 没有完整限制允许提交的批次状态，需阻止已签发批次重新进入审批。
- 工作区最新进程池代码在写入证书后才检查任务租约，而且进度与租约更新位于结果循环结束之后，存在长任务过期和旧 worker 写入风险。不要未修复就直接部署。
- 逐张填写 published_at 会让文件准备与批次发布混为一谈；查询、单张下载和整批下载需共同落实全批完成后发布，不能只修改列表过滤。
- 初次并发生成部门签名密钥的竞争、签发前印章启用状态复核，以及真正的签名验证需要补测。
