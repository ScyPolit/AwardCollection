# 校赛电子证书系统开发任务

更新日期：2026 年 11 月 6 日。

已完成需求讨论和技术方向整理。以下首期开发任务尚未实施；验收项是后续开发必须验证的场景，不代表已运行测试。业务依据见 [需求说明](requirements.md)，部署与一致性设计见 [技术方案](technical-plan.md)。

## 首期里程碑

| 阶段 | 任务 | 验收重点 |
| --- | --- | --- |
| M0 | 验证中文排版、长名单和多部门 PDF 自签 | 缺字与溢出检测；第二个签名不使第一个失效；图片与 PDF 视觉一致 |
| M1 | Pure Admin 基础、Django API、PostgreSQL 和 Docker Compose | 服务可启动、持久化卷可重建、配置与初始化可复现 |
| M2 | 账号、部门、授权和竞赛协作 | 一个账号多部门、一个竞赛多负责人、后端数据隔离及本人回避 |
| M3 | 全校共享模板库、可视化编辑和多枚公章 | 发布部门维护、复制修改、模板和印章版本留存 |
| M4 | 统一 Excel、预览、批次版本和并行会签 | 创建竞赛无需批准；名单整批审批；退回及直接修改均可用 |
| M5 | 自动签发、任务进度、PDF 与图片、下载压缩包 | 全批通过自动入队、重试不重号、重启能恢复、权限下载 |
| M6 | 编号查验、公开字段配置、作废和超管应急 | 公众验证码、管理员免验证码、作废审核期间仍有效、应急留痕 |
| M7 | 站内消息、本机备份、长期留存和上线验证 | 恢复演练、5000 团队批次测试、部署与维护说明 |

## 必须覆盖的验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 负责人创建涉及两部门的竞赛 | 创建提交即生效，不等待用印审批 |
| A02 | 一个负责人关联两个部门；一个竞赛安排多位负责人 | 按授权协作，操作人员可追溯 |
| A03 | 同一部门配置多位管理员 | 任意一位符合回避要求的管理员可完成本部门审批 |
| A04 | 同一批由两个或更多部门会签，仅部分通过 | 不签发；所有部门通过才触发生成 |
| A05 | 有管理员退回并标记问题行 | 整批退回，不发布已单独通过的记录 |
| A06 | 负责人或管理员修改已部分通过的名单 | 产生新版本，旧批准不能继续生效，全部重新审批 |
| A07 | 提交或修改过名单的人尝试普通审批 | 服务端拒绝，不能通过直接调用 API 绕过 |
| A08 | 两位负责人同时修改或管理员批准旧页面版本 | 返回版本冲突，避免静默覆盖和批准错版 |
| A09 | 最后两项审批并发完成 | 只创建一个正式签发任务 |
| A10 | 团队成员姓名必填，未提供学号与学院 | 正常填报；同名仅提示核对，不认定为同一人 |
| A11 | 自由填写奖项与竞赛预设不一致 | 允许填写，随整批审批，不因不在预设而拒绝 |
| A12 | 长作品名、超长成员名单及缺字 | 自动适配；仍不满足时指出记录并阻止提交 |
| A13 | 其他部门选用并尝试修改模板 | 可选用和复制，原模板仍由发布部门维护 |
| A14 | 模板或公章更新后重新访问历史证书 | 历史文件及使用版本不变 |
| A15 | 多部门、多枚公章生成签名 PDF | 用印与获批版本一致，各部门签名检查符合预期 |
| A16 | 输出选择图片或 PDF 加图片 | 仍是一张证书一个编号，签名 PDF 原件可归档 |
| A17 | worker 在生成中被终止后恢复或超时重领 | 可继续执行，旧进程不能覆盖新结果，不重复发证 |
| A18 | 批次部分文件生成失败 | 显示具体失败与进度；重试使用原记录，全批就绪后发布 |
| A19 | 多任务并发生成编号，失败后再重试 | 编号全局唯一，已占用编号不转给其他证书 |
| A20 | 访客按编号查验，复用或伪造验证码 | 每次服务端校验，限制重用及高频枚举 |
| A21 | 管理员在有权限的界面一键查验 | 无需验证码，仍受服务端权限约束 |
| A22 | 修改全校公开字段和姓名脱敏设置 | 公开查询按统一设置返回，内部字段不泄露 |
| A23 | 未获授权的账号访问他部门记录或直接下载地址 | 访问被拒绝，必要的操作留痕 |
| A24 | 作废仅部分部门同意，或申请被驳回 | 原证书继续有效，可正常查验和下载 |
| A25 | 作废取得全部部门批准 | 状态转作废，原编号和历史保留，不覆盖原件 |
| A26 | 超管直接应急签发或作废 | 必须复核密码和填写原因，记录实际操作并通知相关人员 |
| A27 | 清理临时文件和普通日志 | 不影响正式文件、审批、用印和作废历史 |
| A28 | 重建应用容器并执行本机备份恢复演练 | 业务持久化；隔离恢复后记录、文件和签名资料可核对 |
| A29 | 单批 5000 团队运行并同时使用管理和编号查验 | 不丢记录、不重复签发，记录实际耗时、资源和查询响应 |
| A30 | 校园网环境无运行时外部服务可用 | 页面资源、字体、验证码、通知和签发不依赖付费或外部在线接口 |

## 后期功能任务

| 编号 | 任务 | 分期与边界 |
| --- | --- | --- |
| P01 | 团队成员每人一张证书 | 用户明确放入后期，首期每队一张 |

## 首期范围约束

首期不增加个人及教师单独证书、学生领取下载、邮件短信、统一身份认证、动态口令登录、独立防伪码、二维码或用户上传文件验签，也不强制接入外部收费服务。

内部 PDF 签名质量检查属于签发过程，继续在首期执行。编号水印属于模板排版，继续在首期提供。公开查验按照编号返回平台记录，保留验证码和管理员免验证码核验。
