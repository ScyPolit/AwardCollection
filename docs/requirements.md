# 校赛电子证书系统需求说明

更新日期：2026 年 11 月 6 日。

系统用于批量签发团队获奖电子证书。首期完成名单导入、部门会签、可视化模板、公章管理、PDF 自签、图片输出和证书编号查验，部署在学校现有服务器的校园网环境中。

以下“已确认需求”整理自需求讨论。“设计默认项”用于补全实施细节，单独列出，便于后续复核；开发任务和验收计划见 [开发任务](roadmap.md)。

## 已确认的首期范围

| 编号 | 功能 | 已确认规则 |
| --- | --- | --- |
| R01 | 获奖对象 | 首期仅团队证书，每队一张；成员仅要求姓名，证书展示字段可选 |
| R02 | 后台角色 | 超管、部门管理员、竞赛负责人三类角色 |
| R03 | 竞赛创建 | 部门管理员和负责人均可创建，提交即生效；创建本身不触发部门会签 |
| R04 | 负责人协作 | 竞赛负责人为独立角色，不绑定部门；部门管理员可管理多个部门，一项竞赛可由多位负责人共同管理 |
| R05 | 名单导入 | 使用统一 Excel 模板，奖项可自由填写，也可在创建竞赛时预设供选用 |
| R06 | 审批单位 | 整批审批，允许标记问题记录，不进行逐条批准或部分签发 |
| R07 | 部门会签 | 全部拟盖章部门并行审批；同一部门任意一位合格管理员通过即可 |
| R08 | 修改与回避 | 支持整批退回及管理员直接修改；修改后全体重审，提交或修改人员回避日常审批 |
| R09 | 签发触发 | 全部会签通过后自动创建后台任务，无需管理员再次点击确认签发 |
| R10 | 模板库 | 全校共享；发布部门维护原模板，其他部门可复制后另存修改 |
| R11 | 批次模板 | 同一批只使用一套模板，不同批次可以选择不同模板 |
| R12 | 公章 | 各部门自行上传、更换、启用、停用，可以同时启用多枚，历史版本留存 |
| R13 | 输出 | 可选 PDF、图片或 PDF 加图片，PDF 使用自签数字证书签名 |
| R14 | 证书编号 | 系统统一自动生成，全校唯一，签发后固定，作废编号不复用 |
| R15 | 下载发放 | 相关管理员及负责人可下载授权范围内单张证书和整批压缩包 |
| R16 | 编号查验 | 首期按证书编号查询记录与有效状态；公众每次查验需要验证码，管理员可一键免验证码核验 |
| R17 | 公开信息 | 管理员全校统一配置公开字段，以及成员姓名是否脱敏 |
| R18 | 作废 | 需全部盖章部门会签；审批期间原证书继续有效并可正常下载 |
| R19 | 超管应急 | 超管可直接签发或作废；必须填写原因、再次验证密码、留痕并通知相关人员 |
| R20 | 登录和通知 | 独立账号密码；限制登录失败次数；敏感操作再次验证密码；仅站内通知 |
| R21 | 留存和备份 | 正式证书与关键业务记录长期保留；首期仅本机定时备份 |
| R22 | 部署与规模 | Ubuntu 22 系列、Docker、校园网；单批设计规模最多 5000 支团队 |
| R23 | 费用 | 不接入必须付费的服务，不以购买数字证书、验证码或消息服务为首期前提 |

## 角色与数据范围

| 角色 | 业务范围 | 约束 |
| --- | --- | --- |
| 超管 | 全部部门管理员权限、账号与部门、系统配置、日志维护、竞赛启用/废止，以及应急签发和作废 | 应急操作使用专用入口，填写原因并再次验证密码；记录真实操作人 |
| 部门管理员 | 创建或授予独立负责人角色，管理本部门公章、自己部门发布的模板；创建竞赛，处理相关批次审批与作废 | 只能操作授权范围内的数据；提交或修改过本批名单的管理员回避日常审批 |
| 竞赛负责人 | 创建竞赛，协作导入、修改、提交获奖名单，预览和下载授权范围内证书 | 不取得部门用印批准权；按所创建或协作的竞赛控制数据范围 |

负责人不再建立部门关联；竞赛的拟盖章部门仅决定会签和用印范围。超管和部门管理员可创建负责人。旧关联仅留作历史和回滚兼容，不参与新的权限判断。竞赛协作者的新增、移除和操作都记录实际人员。首期不增加学生后台账号，校内访客使用编号查验入口。

部门内部可以配置多位管理员。若提交人或修改人也是本部门管理员，本部门应由其他有权限的管理员审批；人员不足时不能将普通审批自动视为通过。超管应急作为明确的业务例外单独记录。

## 竞赛与填报

创建竞赛时填写竞赛基本信息、负责人、拟盖章部门及相关默认设置。创建提交后即可进行后续工作，名单申请签发时才触发部门会签。

奖项名称允许自由填写。创建竞赛时可以预设常用奖项供选用，预设内容不构成禁止填写其他奖项的名单限制。最终奖项随整批名单审批。

团队成员以姓名为必填信息，不强制提供学号、所属学院，也不依赖学生名册或学生查询接口。姓名相同只能作为核对提示，不能据此自动认定为同一学生或删除记录。

统一 Excel 模板的初始列建议如下，具体列名在开发填报模板时固定：

| 字段 | 初始填报规则 | 证书展示 |
| --- | --- | --- |
| 团队成员 | 必填，一个团队对应一条获奖记录 | 可由模板选择是否展示 |
| 奖项 | 必填，自由文本，可参考竞赛预设 | 可由模板选择是否展示 |
| 团队名称 | 选填 | 可选 |
| 作品名称 | 选填 | 可选 |
| 项目类别 | 选填 | 可选 |
| 指导教师 | 选填，可记录多位 | 可选；首期不单独生成教师证书 |
| 备注 | 选填，用于后台说明 | 默认不进入证书 |

竞赛名称、颁发日期、拟盖章部门等公共信息由批次配置提供，避免要求负责人在每行重复填写。成员和教师的分隔方式应在下载模板中给出清晰示例。

导入应返回具体行号、字段和错误原因。检查必填项、格式、空行、疑似重复和排版问题；修改记录保留原始导入文件及后续变更历史。

## 模板与可视化排版

部门管理员在可视化编辑器中选择背景、文本和数据字段，调整字体、字号、颜色、对齐、位置、文本区域、行距和换行规则。成员、作品、项目类别、指导教师等信息均可选择是否显示。

模板需要支持公章位置和尺寸调整，以及证书编号在正文、编号水印中的独立显示设置。编号水印可调整位置和样式。独立防伪码及其水印不进入首期。

模板发布到全校共享库。原发布部门维护其模板，其他部门可以直接选用，修改时复制为自己的模板。模板保存版本，已提交审批的批次使用对应版本，模板后续更新不覆盖已签发证书。

每个批次使用一套模板；背景和排版在同批内保持同一模板规则，数据内容按团队填入。

长作品名或长成员名单优先自动换行，并在设定范围内缩小字号。达到最小字号后仍溢出，或者出现缺字、重叠等问题时，应提示具体记录，处理后才能提交审批。

证书编号在正文和编号水印中均可隐藏；若全部隐藏，查验人需由发放人员另行取得编号。编辑器应让管理员明确看到这一配置结果。

## 提交与部门会签

正常流程为：创建竞赛、导入名单、检查数据与排版、确认模板及拟用印章、整批提交、部门并行会签、自动排队生成、签发完成、下载发放。

提交时冻结本次审批的数据、模板、印章引用、输出设置和拟盖章部门。每个部门针对同一提交版本作出决定：

1. 全部拟盖章部门都完成批准，批次才取得签发条件。
2. 同一部门任意一位有权限且不需回避的管理员批准，即完成该部门审批。
3. 任一部门退回，整批不得签发；管理员可标记具体问题行。
4. 支持负责人按退回意见修改，也支持管理员直接修改。
5. 直接修改记录前后内容并生成新版本；已有审批结果失效，全部盖章部门重新审批。
6. 日常审批执行本人回避，提交或直接修改过本批名单的人不能审批该批名单。
7. 并发操作须防止旧页面批准新版本、多人互相覆盖修改，或重复触发签发。

超管应急不伪造普通部门审批记录。应急操作单独记录原因、操作人、涉及版本、证书范围和处理结果，并通知相关部门及负责人。

## 公章与 PDF 自签

每个部门独立管理其公章图案，可以同时有多枚在用公章。上传、更换、启停和实际用印均留痕，无需超管逐次审批启用。每次签发必须明确所使用的印章和版本。

公章原文件和签名私钥按权限保护，不能作为无鉴权静态资源提供。历史证书保留当时的印章版本、签发文件和用印记录，更换公章不重写历史证书。

首期保留自签数字证书方案，商业数字证书及第三方签章平台延后。多部门证书需同时体现获批的公章与相应签署信息。

PDF 可通过数字签名检查签署内容的完整性；自签证书需要建立信任关系，阅读器可能提示签署身份未知。图片不携带 PDF 数字签名。自签方案不附带第三方身份背书或可信时间戳服务。[Adobe 信任关系说明](https://www.adobe.com/devnet-docs/acrobatetk/tools/DigSigDC/planning.html#pki-trust)

即使选择仅发放图片，系统也保留签名 PDF 原件作为归档版本。PDF、图片和整批压缩包均与同一证书编号及签发记录关联。

## 自动生成与下载

全部部门批准后自动创建后台任务，不再增加一次普通管理员确认签发。任务支持进度展示、失败原因、重试及中断恢复，重试不得生成重复证书记录或重复编号。

设计规模为单批最多 5000 支团队，每队一张证书。PDF、图片或组合输出是同一证书的不同文件形式，不另行计为新的证书。

相关部门管理员和竞赛负责人可在授权范围内下载单张证书或整批压缩包，再通过学校现有渠道发放。首期编号查验页面不提供学生文件领取下载。

## 编号与查验

编号由系统按全校统一规则自动生成，不允许负责人在 Excel 中指定编号。签发后编号固定，作废或生成失败使用过的编号均不分配给另一张证书。

首期查验方式为输入证书编号查询平台记录。校内访客每次查验需要验证码；管理员登录后可一键免验证码核验，服务端仍检查身份与查询权限。

验证码采用不依赖付费服务的本地方案，并配合服务端查询限流。不能仅在前端判断验证码通过或管理员身份。

全校统一配置公开字段和成员姓名脱敏规则。查验结果显示证书当前有效状态，并按配置展示公开信息，不泄露审批意见、原始导入文件或内部操作日志。

编号查验用于核对平台记录和证书内容，不承担上传文件的完整性检验。独立防伪码、二维码查验、PDF 上传验签和图片原件比对放入后期。

## 作废与纠错

正常作废流程由全部原盖章部门并行审批，同一部门仍按任意一位合格管理员通过的规则处理。审批期间原证书继续有效，可以正常查验、下载；全部批准后才变为作废。

任一部门驳回作废申请，原证书保持有效。申请、审批决定、原因和实际人员长期留痕。作废后保留原文件及历史，不将原文件覆盖为纠正后的内容。

纠错重发使用新提交版本重新审批，并生成新证书编号，关联原证书便于追溯。超管可按已确认的应急规则直接作废。

## 账号安全与通知

使用独立账号密码，由超管创建部门管理员，部门管理员创建或关联负责人账号。首期采用密码登录，限制连续登录失败次数，敏感操作再次验证密码。

高风险操作至少包括应急签发、应急作废、重要账号授权和签章相关变更。认证和权限检查在服务端执行，修改权限后及时影响后续访问。

业务通知仅采用站内消息、待办列表和未读提醒，覆盖审批待办、退回、签发结果、作废结果和超管应急操作。

## 留存与备份

正式证书、获奖数据、审批记录、用印记录、作废记录和关键业务变更长期保留。临时预览文件及普通运行日志按配置期限清理，清理不得影响正式证书与关键业务记录。

首期实现本机定时备份，纳入数据库、证书文件、模板、字体依赖和恢复所需密钥材料，密钥加密保护。需要提供备份结果、失败提醒和恢复操作说明，并实际演练恢复。

现阶段没有服务器外的备份位置，也不安排定期下载备份到其他设备。本机备份用于既定范围内的恢复；整机或存储损坏可能使原件和备份同时丢失。异机备份列为待落实事项。

## 部署条件

使用学校现有 Ubuntu 22 系列服务器或虚拟机，通过 Docker 部署。首期后台和编号查验均仅校园网可访问，校外访问放在后续网络条件具备后开放。

不新增付费服务。数字证书、验证码和消息通知均不依赖购买第三方接口。服务器、磁盘和运维使用学校现有资源。

部署前待核实：Ubuntu 小版本、CPU 架构与核心数、内存、可用磁盘、稳定的校内访问地址、HTTPS 接入条件，以及可用的备份保存空间。性能验收在实际服务器上进行。

## 2026-11-06 体验反馈后的新增与修正

- 统一模板工具栏的宽度、左边距和垂直间距；文字预览与 PDF 共用字体、行距、换行及基线坐标。
- 信息列表提供明确的查看入口：操作日志完整内容、公章图片及历史版本、竞赛状态与协作人、账号角色、证书完整字段、名单记录、审批信息和消息详情。
- 字体选择包括黑体、宋体、楷体、仿宋和常用英文风格。使用可免费分发的内置字体，并支持所有已登录用户导入具备系统使用授权的静态 TTF/TTC；缺字不得静默生成乱码。
- 超管可启用、废止竞赛；废止后保留已签发证书和历史记录，阻止新批次、提交及后续审批。
- 新建账号应有表单校验、等待状态、明确失败提示和重复账号保护；取消不能触发创建。创建负责人无需选择部门。
- 超管继承所有部门管理员能力，包括普通签发审批与作废会签；普通审批继续遵守提交、修改人员回避，应急例外仍需密码复核和原因。
- 增加类似商城的可视化模板选用页，使用现成开源页面模板，不重新设计页面视觉。提供真实缩略图、搜索、维护部门筛选、预览、选用和复制后编辑。

- 按 2026-11-07 最新权限要求，竞赛负责人不显示公章管理、字体管理及模板编辑器，接口同步限制访问；管理员可导入和预览授权字体，超管另可重命名、停用及重新启用。停用不删除原文件，不影响历史模板与已签发证书。

## 2026-11-07 权限与性能改进

- 部门管理员的公章列表、预览和修改均限本部门。批次、证书、撤销、下载与通知按冻结会签部门筛选；竞赛负责人按创建或协作的竞赛筛选。历史会签不因后续竞赛部门调整而改变。
- 模板列表只返回摘要，进入编辑器才读取画布；获奖名单详情每页 50 条，证书档案分页查询。图片及预览按可见区域加载。
- ZIP 在服务器后台排队、去重、校验并完整落盘后才提供下载链接；文件准备进度和完成通知实时更新。Nginx 校验登录授权后直接传输，支持单段 Range 断点续传，不通过浏览器 Blob 缓存整包。
- 生成默认一个进程，只保持有限在途任务；PNG 由签名 PDF 生成并限制像素数。中断重试可补生成缺失 PNG，保持已完成签名 PDF 原件不变。
- 列表、详情、模板编辑器、图片、工作台和通知使用各自的骨架屏或加载提示；失败提供局部错误信息。加载不覆盖菜单与整个页面。

证书编辑器保留页面添加、复制、排序、文本和图形编辑、撤销及文件格式导入。移除右上角 GitHub 图标、演示入口、放映快捷键及动画/切换面板；界面使用“页面”“证书模板”等业务用语。预置内容改为常用证书排版，复用现有可编辑布局，提供添加新页、确认替换当前页和撤销。许可与修改版源码入口保留在关于信息中。
- 前端沿用 Pure Admin 组件与主题，商城卡片内容及按钮对齐，兼顾浅色、深色模式与手机屏宽；证书画布保留最终导出颜色。

- 文字增加加粗、斜体、下划线组合选项；矩形、椭圆、直线和自由绘制可保存到模板，并在 PDF/PNG 中输出。图形支持位置、尺寸、线宽、线色、层级；封闭图形支持填充。
- 系统各处校徽采用用户提供图片的左侧图案，覆盖登录、侧栏、横向导航和浏览器标签图标，兼顾深色模式可见性。
